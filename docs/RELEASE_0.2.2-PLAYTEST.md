# 0.2.2 playtest

Nothing in 0.2.2 ships until every line below has been played, ranked, approved, optimised and stress-tested. Use these marks:
- **Rank:** 1 (cut it) to 5 (love it).
- **Verdict:** ship, rework, or cut.
- **Notes:** a few words.

The build to play is the 0.2.2 candidate:
- `delve/integration-20261012`
- Muse's track and horse work
- the kingdom map and the floor plates, once they land

## How to test

- **Party sizes:** play every game solo and with friends. Browser seats count. Several knights must all play at once, with no spectators.
- **Seats:** every seat checks its own screen and camera.
- **Clean starts:** test each game on a fresh realm and on an old save.
- **What to watch:** stutter, frame drops, text overlapping sprites, any key that does two things, anything that shows a hash or id string.

## Optimise and stress test

None of this is approved until these hold. They're run after the games are approved, so the numbers come from the build that ships.

- **Frame time:** the arena render at terminal and browser sizes, in the busiest room of each new place. Bosses mid-pattern, privy pop-up, kingdom map at full party. No regression against 0.2.1.
- **Four-knight stress:** four seats (two browser), a full delve to floor 6, every new boss, the hostile-shot cap reached. No desync, no stall, no growing memory.
- **Long session:** an hour on the surface with all games played twice. Memory flat, saves round-trip.
- **Old saves:** a 0.2.1 realm loads with nothing lost: stable, barony, college, ranch, countryside.
- **Cargo suite and `npm run test:release`** green before `release-public.sh`. Run `release:evidence` before it too.
