# Development loop: startup, freshness and rebuild cost (2026-10-28)

## Outcome so far

The normal `angelX` source path still builds synchronously from current source,
with full default features, Glass compiled in, browser assets retained, and the
sandbox helper included. No stale-image launch, no background-build substitution,
and no `ANGEL_NO_BUILD` shortcut is used to claim an improvement.

Changes this iteration:

* Leave only `angelX-cockpit` at opt=0 in the incremental `fast` profile. Engine,
  Delve, window and third-party dependencies remain optimized. Release/optimized
  qualification is unchanged.
* Use Cargo for `ANGEL_BUILD_BACKEND=auto` even if Blaze is installed. Keep the
  pinned Blaze wrapper available with **explicit** `ANGEL_BUILD_BACKEND=blaze`.
  It failed a real edit→restore freshness check; making it the default would be
  an unsafe latency shortcut. No compiler or application sandbox was weakened.
* Respect `RUSTUP_HOME` when locating the pinned compiler, including paths with
  spaces, and determine its host with the installed rustc before invoking PATH
  shims. Reusing an installed compiler must not depend on application HOME or
  open an unrelated mise trust/provisioning prompt.
* Make the launcher's unconditional `mise env --json` opt-in with
  `ANGEL_RESOLVE_MISE=1`. An isolated PTY fixture reproduced mise's interactive
  trust prompt before the application could open. The normal launcher now
  inherits terminal PATH; trusted explicit wrapper resolution remains available.
* Retain reproducible bounded semantic-edit/restore and offline PTY probes under
  `scripts/perf/`, with exclusive result names and process-group cleanup.

## Same-toolchain rebuild measurement

Actual full-feature source launches on this machine, same `runtime_paths.rs`
semantic probe, stable Rust 1.95.0, Cargo, profile `fast`. Each edit injected a
unique `_dev_rebuild_probe` in `--build-info --json`; the executed image had to
contain it, then lose it on restoration. Both Cargo configurations passed both
checks. No application model turns, remote jobs or benchmark submissions were
made. One self-model read-only review inspected the stale-image evidence.

| Observation (seconds) | Cargo opt=1 | Cargo opt=0 |
| --- | ---: | ---: |
| Initial prime (not unchanged startup) | 45.086 | 115.246 |
| Unchanged launch 1 | 0.284 | 0.255 |
| Unchanged launch 2 | 0.267 | 0.257 |
| Unchanged launch 3 | 0.288 | 0.260 |

One paired case, not a universal distribution: **2.57× faster / 61.1% less time**

cold-build comparison. Opt=0 grows the local image from roughly 196 MiB to
250 MiB; startup/responsiveness must be checked separately. No claim that every
code path becomes faster at runtime, or that all game/frame-time work benefits.

## Blaze finding: build exit 0 is not image freshness

The pinned wrapper is revision `b383b0bcf5da33816809b00a37e1c36a0e761efb`
with nightly `2026-10-27`, its own `cockpit/target/blaze` tree. Baseline:

* Prime 50.450 s, unchanged launches 0.425 / 0.879 / 0.408 s.
* Semantic edit 83.414 s; marker observed in the executed image.
* Restore build 55.955 s, exit 0; **marker still present**, restore gate failed.
* Both executed images had SHA-256
  `5eed1a09c4f91b138f1a7de03b1957ca8b071c13a2b77600126c7b9f42f346d5`.
  Source digest had been restored to
  `e1ea1bf8006c10c1e0022fb73a8f5fd48f59fc587ca558fa43dbe6616675df8a`.
* The wrapper's attempted daemon build failed inside its build-script sandbox
  (read-only cache / nested build-script wrapper), then ran Rust fallback.
  Sandbox policy was **not** disabled to get a faster number.

Inspection found the published image, rustc named output, and Blaze saved
`programs/.../cargo` image were the same inode and retained the semantic-edit
time. `bin/angelX` takes a new private snapshot on each launch, so this is not
private-copy reuse: copying an already stale image preserves staleness.
Blaze `cargo/state.rs` uses hardlinks for saved Cargo output (`cargo_has`, `place`)
and restores saved images (`give_back`/publication). `cargo/wrapper.rs` starts a
detached settler that runs after Cargo exits. These are relevant suspect paths,
not a proven single-line upstream cause. An independent read-only reviewer also
recommended quarantining automatic selection, not trusting successful fallback.

### Gate for automatic Blaze promotion

1. Fix synchronous fresh-output publication and interactions with saved-image
   aliases/background settling in the pinned compiler; no application sandbox
   weakening and no arbitrary unsandboxed-script allowlist.
2. Qualify repeated edit→restore→unchanged cycles with executable hashes and
   semantic markers, including fallback and daemon-success paths.
3. Establish a clean daemon-host build (no recursive build-script wrapper).
4. Beat the qualified Cargo edit latency under the same features/toolchain
   controls, then check first draft/typed-input and representative runtime work.
5. Only then enable automatic Blaze selection. Merely installing its binaries,
   running `--version`, or shortening discovery is not that qualification.

## Verification and limitations

Existing launcher entry point: `node --test tests/scripts/native-launch.test.mjs`:
**34 passed**, zero failures before adding the mise regression; subsequent
targeted checks for pinned compiler lookup, explicit Blaze and mise opt-in also
passed (4 and 2 tests respectively). The harness reports these as host-runtime test
observations, not independently trusted/reward-labelled qualification.

Actual Cargo semantic-edit/restore measurements both exited 0 and verified
image contents. Default features, browser bundle generation and helper build
were not disabled. No broad overlapping full test suite was run.

Final offline 140×40 PTY observation (3 samples per path):

| Path | Draft visible (ms) | Typed input echo (ms) |
| --- | --- | --- |
| Normal source launcher | 301.18 / 283.23 / 271.48 | 0.92 / 0.54 / 0.51 |
| Direct full-feature image | 55.36 / 58.72 / 57.35 | 0.63 / 0.84 / 0.63 |

Receipts: `reports/performance/terminal-opt0-launcher-no-mise-20261028.json`
and `terminal-opt0-direct-no-mise-20261028.json`. Fixture priming is separately
accounted for, not hidden in the unchanged samples. The source launch still runs
Cargo freshness checks. Fixture HOME is shared during the samples; changing HOME
is a real Cargo build-script input, not an unchanged startup. Source cartridges
are retained; runtime state is isolated. The probe sends a draft and types text,
then terminates/reaps its own process group without submitting a model turn.

The fixture turns off discovery/background services and uses offline practice;
this is **not** a provider, Glass or cold-filesystem benchmark. Negative attempts
are retained too. A stripped environment omitted TMPDIR, causing the C compiler
to exhaust `/tmp` quota (`terminal-opt0-launcher-diagnostic-20261028.prime.log`).
After fixing fixture TMPDIR, two attempts hit mise's interactive trust prompt.
The final run passed after the launcher's PATH refresh became explicit opt-in.
The original direct-image observations are retained, not substituted for final
launcher readiness. All completed probes restored source bytes and final normal
source-image compilation succeeded.

Available disk fell from 9.9 GiB to about 3.8 GiB while exercising compiler
profiles. No operator caches or unrelated artifacts were deleted. Cache growth
is a concrete remaining long-term-dev concern; a safe, explicit retention tool
is preferable to secretly cleaning a developer's build tree.

## Normal use

```
angelX                          # current source, incremental fast, safe auto backend
angelX build                    # prewarm current source without starting the UI
angelX setup                    # model setup through the same source freshness path
angelX build --release          # slower optimized build, unchanged
ANGEL_BUILD_BACKEND=blaze angelX # explicit, unqualified compiler experiment only
```

Native reloadable router modules remain available with `ANGEL_NATIVE_MODULES=1`
and `angelX build --modules`; this iteration did not silently enable them or
claim they accelerate unrelated Rust edits. No Delve browser-loop/FPS work or
new game systems were resumed.
