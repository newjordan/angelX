# angel0 competition/RL runner

angel0 exposes one supported machine seam: the compiled `angel --task-json`
command. It runs one tool-using policy turn inside an explicit workspace and
prints exactly one `angel.task_result` JSON object to stdout. Progress,
diagnostics, and tool events go to stderr.

This is the v1 runner surface. The interactive `/campaign` and `/rl` commands
are operator/research views, not public headless runner APIs.

## Build

The qualified producer target is Linux x86_64 with glibc and the pinned Rust
toolchain. The public action producer additionally requires a supported Node
version, Git, `/usr/bin/bwrap`, and working unprivileged user namespaces; it
fails as `infrastructure/isolation` when that sandbox cannot be established.

From a source checkout or extracted source release:

```bash
cargo build --manifest-path cockpit/Cargo.toml --locked --release --no-default-features
cockpit/target/release/angel --version
cockpit/target/release/angel --help
install -Dm0755 cockpit/target/release/angel "$HOME/.local/bin/angel"
```

`bin/angel0` performs the same locked, no-default-feature build automatically
for headless commands. It preserves stdout and stderr, refuses to fall back to a
stale binary after a failed runner build, skips the WebGPU portal, and never
loads broad home-directory env files. Pass an explicitly trusted shell env file
with `ANGEL_RUNNER_ENV_FILE=/path/to/runner.env`, or export only the required
provider variables in the invoking process.

## Provider-free transport smoke

The practice route proves the CLI, result envelope, limits, and rollout store
without credentials or network access. It does not prove coding quality or earn
a task reward. `--max-hops` and `--deadline-secs` both default to `0`, which
`angel --help` documents as unbounded; a positive value opts in to a ceiling.
Always pass explicit positive limits for scored runs. Headless mode also refuses
the offline practice route unless the caller opts in with `ANGEL_PRACTICE=1`;
without it the runner exits with `no_route`.

```bash
smoke_workspace="$(mktemp -d)"
printf '%s\n' 'Return a short runner transport acknowledgement.' | \
ANGEL_PRACTICE=1 bin/angel0 --task-json \
  --driver practice \
  --workspace "$smoke_workspace" \
  --task-id transport-smoke \
  --run-id local-smoke-1 \
  --max-hops 2 \
  --deadline-secs 30 \
  --tool-profile essential \
  --rollout shadow \
  --require-rollout \
  >result.json
jq -e '.kind == "angel.task_result" and .runtime.schema == "angel-task-runtime/v1"' result.json
```

## A scored coding attempt

Use a fresh disposable workspace for every attempt. Pin finite limits, stable
task/run IDs, the route and reasoning policy, and required local capture:

```bash
printf '%s\n' 'Implement the task described by the checked-in TASK.md.' | \
bin/angel0 --task-json \
  --workspace /absolute/path/to/disposable-attempt \
  --task-id suite.case-17 \
  --run-id candidate-a.seed-3 \
  --driver openai \
  --reasoning-effort high \
  --max-hops 64 \
  --deadline-secs 900 \
  --tool-profile essential \
  --rollout local \
  --require-rollout \
  >attempt.json
```

Never use `--yolo` for a sealed or scored run. The runner result records whether
the unrestricted profile was active so an evaluator can reject it.
Passing held-out prompt text on stdin also keeps it out of host process listings.

Run the deterministic verifier only after Angel exits, in an evaluator-owned
sandbox with the candidate workspace mounted read-only, network disabled,
secrets removed, and independent time/output limits. Task mode deliberately
rejects `--accept-cmd`: a model-visible, in-process shell verifier would blur
the policy/reward boundary and expose the host to untrusted task content.

## Result semantics

The envelope is additive and versioned. Important fields are:

- `task_id`, `run_id`, and `workspace` — caller identities and execution root;
- `status` and `stop_reason` — policy/runtime termination, not reward;
- `club`, `model`, and `reasoning_effort` — resolved route identity when known;
- `hops`, `elapsed_ms`, `usage`, and `output_budget` — observed execution cost;
- `runtime` — requested limits/policy, prompt hash, build identity, and a
  canonical `config_sha256`;
- `rollout_id` — the exact harness journal generated by shadow/local capture;
- `artifacts` — bounded references emitted by the runtime.

`status: "completed"` means the model produced an answer. It does not mean the
task passed. Public task mode sets `runtime.verification_policy` to
`external-only`; only the competition's sealed evaluator owns final reward.

Unknown usage/model values are omitted, never replaced with zero or a guessed
identity. A public competition should reject attempts missing identities or
evidence required by its manifest.

## Rollout capture and export

Capture modes are:

- `off` — no journal;
- `shadow` — digests and metadata, without semantic bodies;
- `local` — secret-screened semantic bodies in the private project-keyed store.

`--require-rollout` is valid only with `shadow` or `local`. It makes recorder
startup and terminal sealing part of task success; capture failure is a
structured nonzero runner failure, never a warning attached to a completed run.

Audit the exact ID returned by every task result. The receipt is body-free and
works for sealed rollouts whose reward is owned by the external evaluator:

```bash
rollout_id="$(jq -r '.rollout_id' attempt.json)"
cockpit/target/release/angel \
  --audit-harness-rollout \
  --workspace /absolute/path/to/disposable-attempt \
  "$rollout_id" attempt.rollout-audit.json
```

Audit/export files use create-new private files and refuse overwrite.
The audit receipt exposes only digest-form project identity. Its
`task_binding` seals `task_id`, `run_id`, the operator-prompt hash, canonical
runtime-config hash, runner/build identity, and `binding_sha256`; the top-level
`receipt_sha256` binds the complete body-free receipt. Cross-check those fields,
the termination flags/final-answer digest, and the result's exact `rollout_id`
before accepting an attempt.
`--export-harness-rollout` is intentionally stricter: it emits semantic
`angel-trajectory/v2` data only for finalized, locally captured rollouts whose
reward receipt makes them training-eligible. `--all` exports the eligible
project corpus. An external competition proof is joined to the body-free audit
receipt by `task_id`, `run_id`, `rollout_id`, workspace/fixture digest, and
binary/runtime identities; it does not silently mint an in-store training label.

## Exit codes

| Code | Meaning                                                                     |
| ---: | --------------------------------------------------------------------------- |
|  `0` | The policy produced an answer. Inspect verifier/reward evidence separately. |
|  `1` | Provider, runtime, workspace, or required-capture failure.                  |
|  `2` | Invalid arguments, empty prompt, or startup configuration failure.          |
|  `3` | Guarded stop without an answer under strict task mode.                      |

Do not collapse codes 1–3 into task reward zero without retaining their typed
status. Infrastructure failure, policy truncation, and a verifier-owned task
failure are different training events.

## Reproducibility checklist

A competition wrapper should additionally bind and retain:

- immutable fixture/setup and task-manifest digests;
- the exact angel0 binary SHA-256 and `--build-info --json` receipt;
- a fresh workspace or content-addressed base for every attempt;
- an outer container/bubblewrap boundary for the policy process and a separate
  read-only, networkless verifier boundary;
- red-before/green-after verifier proof and protected-path policy;
- provider/model/reasoning policy plus honest seed semantics (remote inference
  is not deterministic merely because an attempt has a seed label);
- finite hop, wall, provider-output, artifact, and external cost limits;
- the task result, audited rollout, diff, verifier proof, and terminal ledger row.

The public action-agent producer (`benchmarks/action-agent/`: attempt
workspaces, policy launches, graders, and ledgers) is not a release input. As
recorded in [docs/release-evidence.md](../../docs/release-evidence.md), it was
never committed to this repository, so the release archive ships the cockpit,
its launcher, the vendored dependency, and the release policy and verifiers
instead. Real competitions must provide separately controlled tasks and
graders; internal campaign/ablation lifecycle and Prime tooling are likewise
outside the release.
