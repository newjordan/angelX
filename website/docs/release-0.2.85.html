angelX 0.2.85: the speed update

A headless task in a small workspace now starts with its files already read, gets its tests run with every write, and ends the moment the full suite passes. On DeepSeek V4.1 Flash, angelX solved all 136 polyglot tasks on each of three seeds in 19 to 23 minutes. pi 1.5.0, on the same model the same day, solved 127 in 103 minutes.

What makes it fast

These are on for a headless task (angel --task) in a workspace of 40 files or fewer. Set the variable to 0 to turn one off.

  • The files arrive with the task. A small workspace is read before the first request and sent as context, each file whole (ANGEL_TASK_PREREAD_AS_CONTEXT). Package manifests and tool configuration stay out of it; the map still names them (ANGEL_TASK_PREREAD_SKIP_MANIFESTS).

  • Tests run with the write. A response that only writes files gets the test run added to it, so the model sees the write and its tests in one turn (ANGEL_TASK_TEST_AFTER_WRITE).

  • It stops at green. When that test run passes in full, the task ends there with a short notice from angelX instead of one more model call (ANGEL_TASK_END_AT_GREEN).

  • More of the first request is cached. The brevity block now comes ahead of the workspace map (ANGEL_TASK_STABLE_FIRST).

  • A locked loop is sent once. When the model repeats the same failing batch, the request carries one copy of it and the closing turns rotate (ANGEL_LOOP_COLLAPSE).

  • Rust builds once per run. The Rust verifier keeps one private Cargo home for the whole run, so later test runs compile only what changed (ANGEL_CARGO_HOME_REUSE).
